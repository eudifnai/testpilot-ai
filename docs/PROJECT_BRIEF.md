# TestPilot AI 产品开发说明

> 文档用途：本说明用于给 CodeX App / Codex / AI Coding Agent 读取，作为开发 TestPilot AI 项目的需求文档、产品文档和开发指令。

---

## 1. 产品名称

**TestPilot AI**

## 2. 产品定位

TestPilot AI 是一款面向测试工程师、测试开发工程师和中小研发团队的 AI 测试助手平台。

用户可以输入需求文档、接口文档、用户故事、Bug 描述或日志信息，系统自动生成测试点、测试用例、接口测试脚本、Bug 分析报告和测试总结报告，帮助测试人员提升用例设计、接口测试、缺陷分析和测试报告编写效率。

## 3. 产品目标

第一阶段目标是开发一个可运行的 Web MVP，核心能力包括：

1. 用户粘贴需求文本，AI 自动生成测试点。
2. AI 根据测试点生成结构化测试用例。
3. 支持导出测试用例为 Excel。
4. 用户粘贴接口文档，AI 自动生成接口测试用例。
5. 用户输入 Bug 描述、日志、接口返回信息，AI 自动生成 Bug 分析建议。
6. 提供测试报告生成能力。

第一阶段不追求复杂权限系统、不做多租户、不做企业级流程审批，优先实现可演示、可扩展、可二次开发的版本。

## 4. 目标用户

### 4.1 主要用户

测试工程师、测试开发工程师、QA 工程师、软件测试实习生、研发团队中的兼职测试人员。

### 4.2 用户痛点

1. 需求文档较长，人工拆测试点耗时。
2. 测试用例编写重复性高。
3. 边界场景、异常场景容易遗漏。
4. 接口测试用例设计效率低。
5. Bug 描述不够专业，和开发沟通成本高。
6. 测试报告经常需要手工整理。
7. 初级测试工程师缺少系统化测试设计思路。

## 5. 核心价值

TestPilot AI 不替代测试工程师，而是帮助测试工程师完成以下工作：

1. 快速理解需求。
2. 自动拆解测试点。
3. 自动生成测试用例。
4. 补充边界值、异常流和安全测试场景。
5. 生成更专业的 Bug 描述和分析。
6. 快速形成测试报告。
7. 提升测试工作的标准化程度。

## 6. MVP 功能范围

### 6.1 需求解析模块

用户输入需求文本，系统输出：

- 功能点列表
- 业务流程
- 关键规则
- 风险点
- 测试关注点
- 需要确认的问题

### 6.2 测试用例生成模块

用户输入需求文本或选择已解析的测试点，系统生成测试用例表格。

测试用例字段包括：

- 用例编号
- 模块名称
- 测试标题
- 前置条件
- 测试步骤
- 测试数据
- 预期结果
- 优先级
- 用例类型
- 备注

用例类型包括：

- 功能测试
- 边界值测试
- 异常测试
- 兼容性测试
- 安全测试
- 权限测试
- 性能关注点

### 6.3 接口测试生成模块

用户输入接口说明、Swagger 片段、curl 命令或接口字段说明，系统生成接口测试用例。

输出内容包括：

- 接口名称
- 请求方式
- 请求路径
- 请求参数
- 正常场景
- 缺参场景
- 参数类型错误场景
- 边界值场景
- 权限校验场景
- 返回值校验点
- 建议自动化脚本

第一阶段优先生成测试用例，不强制执行真实接口请求。

### 6.4 Bug 分析助手

用户输入：

- Bug 标题
- 复现步骤
- 实际结果
- 预期结果
- 日志信息
- 接口返回
- 控制台错误
- 环境信息

系统输出：

- 标准化 Bug 描述
- 可能原因
- 影响范围
- 严重程度建议
- 优先级建议
- 需要开发排查的方向
- 建议补充的信息
- 可复制到 Jira / 禅道 / 飞书的缺陷单内容

### 6.5 测试报告生成模块

用户输入测试结果数据，系统生成测试报告。

测试报告包括：

- 测试范围
- 测试环境
- 测试版本
- 测试结论
- 用例执行情况
- 缺陷统计
- 风险说明
- 上线建议

### 6.6 Excel 导出

系统支持将测试用例导出为 Excel 文件。

Excel 表头包括：

- 用例编号
- 模块
- 标题
- 前置条件
- 步骤
- 测试数据
- 预期结果
- 优先级
- 类型
- 备注

## 7. 非 MVP 功能

1. 用户登录注册。

3. 多租户隔离。
4. 权限审批。
5. 在线执行自动化测试。

## 10. 后端 API 设计

### 10.1 需求解析接口

请求地址：`POST /api/ai/analyze-requirement`

请求参数：

```json
{
  "requirement_text": "用户输入的需求内容"
}
```

返回参数：

```json
{
  "summary": "需求摘要",
  "features": ["功能点1", "功能点2"],
  "business_flow": ["流程1", "流程2"],
  "test_points": ["测试点1", "测试点2"],
  "risks": ["风险点1", "风险点2"],
  "questions": ["待确认问题1", "待确认问题2"]
}
```

### 10.2 测试用例生成接口

请求地址：`POST /api/ai/generate-testcases`

请求参数：

```json
{
  "requirement_text": "需求内容",
  "case_types": ["functional", "boundary", "exception", "security"],
  "case_count": 20
}
```

返回参数：

```json
{
  "testcases": [
    {
      "case_id": "TC001",
      "module": "登录模块",
      "title": "验证用户使用正确账号密码登录成功",
      "precondition": "用户已注册且账号状态正常",
      "steps": ["打开登录页", "输入账号", "输入密码", "点击登录"],
      "test_data": "账号：test001，密码：123456",
      "expected_result": "登录成功并跳转到首页",
      "priority": "P1",
      "case_type": "功能测试",
      "remark": ""
    }
  ]
}
```

### 10.3 接口测试生成接口

请求地址：`POST /api/ai/generate-api-tests`

请求参数：

```json
{
  "api_doc": "接口说明、Swagger 片段或 curl 内容"
}
```

返回参数：

```json
{
  "api_name": "用户登录接口",
  "method": "POST",
  "path": "/api/login",
  "testcases": [
    {
      "case_id": "API_TC001",
      "title": "正确账号密码登录成功",
      "request_data": {},
      "expected_status": 200,
      "expected_result": "返回 token 和用户信息",
      "case_type": "正常场景"
    }
  ],
  "script_suggestion": "pytest 示例代码"
}
```

### 10.4 Bug 分析接口

请求地址：`POST /api/ai/analyze-bug`

请求参数：

```json
{
  "title": "Bug 标题",
  "steps": "复现步骤",
  "actual_result": "实际结果",
  "expected_result": "预期结果",
  "logs": "日志信息",
  "environment": "测试环境"
}
```

```json
{

  "possible_causes": ["可能原因1", "可能原因2"],
  "severity": "严重",
  "priority": "P1",
  "impact_scope": "影响范围说明",
  "developer_checklist": ["排查建议1", "排查建议2"]
}
```

### 10.5 测试报告生成接口

请求参数：

```json

  "project_name": "项目名称",

  "test_scope": "测试范围",
  "test_result": "测试结果",
```

```json
{
```

## 11. 数据库设计

第一阶段可以使用 SQLite。

### 11.1 generation_records 表

用于保存 AI 生成历史。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PRIMARY KEY | 主键 |
| type | TEXT | 生成类型 |
| input_text | TEXT | 用户输入 |
| output_json | TEXT | AI 输出结果 |
| created_at | DATETIME | 创建时间 |

`type` 可选值：

```text
requirement_analysis
testcase_generation
api_test_generation
bug_analysis
test_report
```

### 11.2 testcases 表

用于保存测试用例。

| 字段 | 类型 | 说明 |

| case_id | TEXT | 用例编号 |
| module | TEXT | 模块 |
| title | TEXT | 标题 |
| precondition | TEXT | 前置条件 |
| steps | TEXT | 测试步骤 |
| test_data | TEXT | 测试数据 |
| expected_result | TEXT | 预期结果 |
| priority | TEXT | 优先级 |
| case_type | TEXT | 用例类型 |
| remark | TEXT | 备注 |
| created_at | DATETIME | 创建时间 |

## 12. AI Prompt 设计

### 12.1 需求解析 Prompt

```text
你是一名资深测试架构师。请根据用户提供的需求文档，提取功能点、业务流程、测试关注点、风险点和待确认问题。

要求：
1. 输出结构化 JSON。
2. 不要编造需求中不存在的功能。
3. 如果需求不明确，请放入 questions 字段。
4. 测试点需要覆盖正常流程、异常流程、边界条件、权限、安全和兼容性。
```

### 12.2 测试用例生成 Prompt

```text
你是一名资深测试工程师。请根据用户提供的需求内容生成测试用例。

要求：
1. 输出 JSON 数组。
2. 每条用例包含 case_id、module、title、precondition、steps、test_data、expected_result、priority、case_type、remark。
3. 用例需要覆盖功能测试、边界值测试、异常测试、权限测试、安全测试。
4. 测试步骤要清晰、可执行。
5. 预期结果要明确、可验证。
6. 不要输出解释性废话，只输出结构化数据。
```

### 12.3 接口测试 Prompt

```text
你是一名接口测试专家。请根据用户提供的接口文档生成接口测试用例。

要求：
1. 识别接口名称、请求方式、路径、参数和返回值。
2. 生成正常场景、缺参场景、参数类型错误、边界值、权限校验、重复提交、异常状态等测试用例。
3. 输出结构化 JSON。
4. 如接口信息缺失，请在 missing_info 字段中说明。
```

### 12.4 Bug 分析 Prompt

```text
你是一名资深测试开发工程师。请根据用户提供的 Bug 信息、日志和环境信息，生成专业的 Bug 分析结果。

要求：
1. 输出标准化 Bug 单。
2. 分析可能原因。
3. 给出严重程度和优先级建议。
4. 给出开发排查清单。
5. 明确还需要补充哪些信息。
```

### 12.5 测试报告 Prompt

```text
你是一名测试负责人。请根据用户输入的测试范围、测试结果、缺陷情况和风险说明，生成一份专业测试报告。

要求：
1. 使用 Markdown 格式。
2. 包含测试结论、测试范围、测试环境、用例执行情况、缺陷统计、风险说明和上线建议。
3. 语言简洁、专业。
4. 上线建议需要基于风险情况给出，不要过度乐观。
```

## 13. 前端交互要求

1. 所有生成按钮需要 loading 状态。
2. AI 生成失败时，需要显示明确错误提示。
3. 所有结果支持复制。
4. 测试用例结果使用表格展示。
5. 测试报告使用 Markdown 预览。
6. 输入框需要提供示例内容。
7. 页面风格简洁、专业，适合测试工具平台。
8. 不需要复杂动画。
9. 优先保证功能完整和代码清晰。

## 14. 安全与配置

后端需要使用 `.env` 文件配置大模型 API Key。

`.env.example` 内容：

```text
OPENAI_API_KEY=
OPENAI_BASE_URL=
MODEL_NAME=
DATABASE_URL=sqlite:///./testpilot.db
```

要求：

1. 不要把真实 API Key 写入代码。
2. 后端读取环境变量。
3. 前端不要直接调用大模型接口。
4. 所有 AI 请求都从后端转发。
5. 后端需要做基础异常处理。
